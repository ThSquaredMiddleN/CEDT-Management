## ปฏิทินและไฟล์ที่ต้องเข้าใจตรงกัน

- วันที่รับคำร้องเป็นวันที่เจ้าหน้าที่ระบุตามประกาศ ปัจจุบันรับถึงสิ้นวัน 23:59 น. ไทย ยังไม่รองรับเส้นตายเป็นเวลาระหว่างวัน
- เก็บวันเริ่ม/สิ้นสุดช่วงเรียนและ Final ได้ แต่ยังไม่คำนวณ 1/3 Block หรือ Final ลบหนึ่งสัปดาห์อัตโนมัติ ไม่เดาการปัดเศษหรือกฎยกเว้น
- แก้ไขเหตุผล/ไฟล์ในคำร้องที่ยื่นแล้วใช้เลขคำร้องและกำหนดเดิม ระบบปัจจุบันไม่ปิดการแก้คำร้องเดิมเพราะเลยวันรับคำร้องใหม่ ต้องให้ผู้ปฏิบัติงานทดลองยืนยันเงื่อนไขการรับแก้จริงก่อนใช้จริง
- PDF แต่ละไฟล์ไม่เกิน 5 MB, 1–100 หน้า ไม่เข้ารหัส รวมได้สองฉบับเป็นไฟล์ใหม่ไม่เกิน 10 MB/200 หน้า เก็บได้ 30 ไฟล์ต่อคำร้อง
- ไฟล์เก็บในฐานข้อมูลของ prototype มีการตรวจสิทธิ์ก่อนดาวน์โหลด ไม่ใช่ public asset และยังไม่มีโครงจัดเก็บไฟล์สำหรับ production ครบ
- การแนบฉบับลงนามไม่ใช่การสร้าง/รับรองลายเซ็นดิจิทัล หากพบฟิลด์ลายเซ็นดิจิทัลใน PDF จะไม่รวมไฟล์เพื่อหลีกเลี่ยงทำให้ลายเซ็นเดิมเสีย ไม่ได้อ้างว่าตรวจความถูกต้องของลายเซ็นได้ทุกชนิด

## เปิดทดลอง

local รอบนี้: `http://localhost:5175/course-change` — รีเฟรชเพื่อโหลด build ใหม่

มีข้อมูลสาธิตแยก `DEMO-CC-V2` สำหรับ `student3@cedt.edu` / `student1234` ตอนเรียน `DEMO` ระบุชัดว่าไม่ใช่วิชาหรือกำหนดการจริง ไม่แก้รายวิชา/คำร้องเดิม

1. เข้านิสิต เลือกถอน เลือกวิชา `DEMO-CC-V2` กรอกเหตุผล ตรวจทาน และยื่น เก็บเลขคำร้อง
2. เข้าเจ้าหน้าที่ `admin@cedt.edu` / `admin1234` ค้นเลขคำร้อง เลือกส่งกลับแก้ไขพร้อมเหตุผล
3. กลับนิสิต เปิดติดตามคำร้อง แก้เหตุผล/แนบไฟล์ แล้วส่งฉบับแก้ไขในคำร้องเดิม
4. เจ้าหน้าที่ตรวจผ่าน บันทึกส่งขอลงนาม แนบ PDF ทดสอบที่ไม่มีข้อมูลจริงในประเภทฉบับลงนาม แล้วยืนยันส่งคืนพร้อมรายละเอียด
5. นิสิตดาวน์โหลดฉบับที่ได้รับคืน บันทึก Reg Chula ด้วยข้อความที่ระบุชัดว่าเป็นการทดลอง แนบ PDF ทดสอบอีกฉบับเป็นเอกสาร Reg เลือกลำดับ รวมไฟล์ และดาวน์โหลดตรวจสอบ
6. นิสิตบันทึกส่ง PI ด้วยหลักฐานอ้างอิงที่ระบุว่าเป็นการทดลอง เจ้าหน้าที่ตรวจเอกสารครบ คำร้องยังอยู่รอผลทะเบียน
7. เจ้าหน้าที่บันทึกผลทะเบียนสาธิตพร้อมหมายเหตุ ไม่อธิบายว่าได้รับผลจากมหาวิทยาลัยจริง
8. ใช้หน้า “กำหนดรายวิชา / Block” ทดลองสร้างฉบับร่าง แก้วันที่ และหยุดประกาศเฉพาะข้อมูลสาธิต หากจะทดลอง flow ใหม่หลังปิดคำร้องแล้ว ต้องใช้กรณีสาธิตอื่น ไม่รีเซ็ตคำร้องเดิม

เตรียมวิชาสาธิตแบบเพิ่มข้อมูลโดยไม่รีเซ็ต: `cd backend` แล้ว `npm run demo:course-change-v2` สคริปต์ไม่เขียนทับกำหนดที่มีอยู่แล้ว และอ้างวันที่เดียวกับ backend ผ่าน `ccToday()`

## ที่ยังต้องยืนยัน/ทำต่อ

1. วันตัดรอบจริงและการคำนวณ 1/3 Block/ก่อน Final กฎรายเส้นทางที่ยังไม่ระบุ Reg/PI และเวลาตัดรอบระหว่างวัน
2. แบบเอกสารจริง ผู้ลงนาม/อำนาจอนุมัติ และวิธีที่หน่วยงานรับรองลายเซ็น/ไฟล์รวม
3. หลักฐานและผู้ยืนยันผลสุดท้าย ปัจจุบันเป็นเจ้าหน้าที่บันทึกด้วยมือ
4. SSO/ข้อมูลลงทะเบียนจริง/API Reg Chula/PI/การแจ้งเตือนภายนอก ยังไม่เชื่อม ไม่รวมอยู่ในการส่งสำเร็จของ v2
5. สิทธิ์ยังใช้ staff ร่วมกัน ต้องแยกบทบาท/มอบหมายตามผู้ปฏิบัติงานที่ยืนยันแล้ว
6. การตรวจหน้าจอ คีย์บอร์ด มือถือ และผู้ใช้งานจริงของ flow ใหม่ รวมถึงความพร้อมติดตั้งจริง/การจัดเก็บไฟล์

ยังไม่ใช่ระบบ production ที่เสร็จและรอแค่ข้อมูลจากพี่นัท

## บันทึกการแก้ข้อผิดพลาดระหว่างพัฒนา

การทดสอบไฟล์เกิน 5 MB ทำซ้ำได้ว่าได้ 500 แทน 413 ทดสอบแยกด้วย Fastify+multipart: ไม่ใช้ custom error handler ได้ 413, ใช้ handler ของแอปได้ 500 ขณะที่ไฟล์เล็กได้ 200 ทั้งคู่ จึงยืนยันว่า handler กลางไม่ได้ส่งต่อกรณี 413 เพิ่มการตอบขนาดเกินในรูปแบบ error ของแอปแล้ว ทดสอบจริงผ่าน ส่วน fixture เดิมที่เคยเปิดตามตารางเทอมเพิ่มกำหนดรายวิชาทดสอบอย่างชัดเจน ไม่ลดเงื่อนไข production เพื่อให้เทสต์ผ่าน
