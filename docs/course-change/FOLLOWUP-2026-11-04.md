# ลด/ถอน — งานเพิ่มเติมรอบ 2 วันที่ 4/11/2569

เพิ่มต่อจาก [flow รุ่นใหม่](IMPLEMENTATION-2026-11-04.md) ตามคำสั่งให้ทำทั้ง 4 ส่วน โดยคงขอบเขตเฉพาะลด/ถอนและไม่แก้ระเบียบที่ยังไม่ยืนยัน

## 1. ข้อความที่ยังไม่ส่ง

- เก็บเหตุผลฉบับแก้ไขและหมายเหตุของขั้นตอน v2 แยกตามบัญชี คำร้อง และ action ใน sessionStorage ของแท็บเดิม ไม่เกิน 24 ชั่วโมง
- ปิดหน้าต่างที่มีข้อความแล้วเลือกเก็บร่าง/ล้างร่าง/แก้ไขต่อได้ เมื่อเปิดขั้นตอนเดิมจะเรียกคืนข้อความ และเตือนเมื่อข้อมูลคำร้องเปลี่ยนจากรุ่นที่เริ่มกรอก
- เก็บผู้รับ วันที่ และหมายเหตุของชุดขอลงนามแยกตามบัญชีและชุดคำร้อง พร้อมปุ่มตรวจผลการบันทึกชุดเดิมหลังการตอบกลับไม่ชัดเจน
- ล้างร่างเมื่อบันทึกสำเร็จ ล้างเอง หรือออกจากระบบ ไม่ส่งร่างอัตโนมัติและไม่ใช่ร่างข้ามอุปกรณ์
- เตือนก่อนรีโหลดเมื่อมีข้อความที่ยังไม่ส่ง/ไฟล์ที่เลือกแต่ยังไม่แนบ หาก storage ใช้ไม่ได้จะแจ้งให้คัดลอกข้อความก่อนปิด การเลือกไฟล์ยังไม่ใช่การอัปโหลด และตัวไฟล์ไม่ได้อยู่ในร่าง
- การป้องกันนี้เพิ่มให้ flow รุ่นใหม่ ไม่เปลี่ยนหน้าปุ่มอนุมัติของคำร้องประวัติ v1

## 2. บันทึกรวบรวมส่งขอลงนามเป็นชุด

- เจ้าหน้าที่เลือกได้ไม่เกิน 50 คำร้องที่กำลังรอลงนาม ต้องเป็นเทอม วิชา Section ประเภท และรอบประกาศเดียวกัน
- ระบุผู้รับ/หน่วยงาน วันที่ส่งจริง และข้อมูลอ้างอิง สร้างเลขชุดและ snapshot รายการ ณ วันที่บันทึก พร้อม CSV สรุปที่เปิดภาษาไทยและป้องกันสูตรในตารางคำนวณ
- คำร้องยังอยู่รอลงนาม ไม่สร้างลายเซ็น ไม่ส่ง Outlook/email เอง และ CSV ไม่ใช่ PDF คำร้องทางการหรือชุดไฟล์เอกสารสำหรับยื่นจริง
- คงประวัติในคำร้องแต่ละรายการ แจ้งในเว็บ และดูประวัติ 20 ชุดล่าสุดพร้อมจำนวนคำร้องที่ยังรอคืน/ที่ไปขั้นถัดไปแล้ว ดาวน์โหลดสรุปย้อนหลังได้
- ล็อกและตรวจ revision ทุกรายการก่อนบันทึก หากรายการใดเปลี่ยนจะไม่บันทึกบางส่วนในชุดเดียวกัน รหัสชุดเดิมกับข้อมูลเดิมลองซ้ำได้โดยไม่สร้างชุด/ประวัติซ้ำ แต่ไม่รับข้อมูลเปลี่ยนโดยใช้รหัสเดิม
- API ใหม่ `GET/POST /course-change/signature-batches` และ `GET /course-change/signature-batches/:id` เป็น staff-only

## 3. เวลาค้างและผู้ทำขั้นถัดไป

- Inbox และรายละเอียดคำร้องใหม่แสดงเวลาที่อยู่ในขั้นปัจจุบัน และผู้ที่ต้องทำต่อ: นิสิต เจ้าหน้าที่ ผู้ลงนาม หรือทะเบียน/สนท.
- นับจากเหตุการณ์เข้าขั้น ไม่เริ่มนับใหม่เมื่อแนบไฟล์ บันทึกหมายเหตุ หรือบันทึกส่งขอลงนามโดยยังอยู่ขั้นเดิม ถ้ากลับมาแก้เอกสารจากขั้นรอผลจึงเริ่มช่วงรอใหม่
- ปรับเวลาแสดงทุกนาที ไม่ตั้ง SLA/เส้นตายหรือสีเตือนจากจำนวนชั่วโมงที่คิดขึ้นเอง และไม่แสดงเป็นงานค้างเมื่อคำร้องปิดแล้ว

## ผลตรวจ

- Backend ทั้งชุด **111/111 ผ่าน** บนฐานแยกที่สร้าง/ลบเฉพาะรอบทดสอบ เพิ่มกรณี batch atomicity, concurrent retry, mixed Section, duplicate membership, สิทธิ์อ่านชุด และเวลารอรายขั้น
- หลังปรับ timeout ของ transaction ชุด ได้รันทดสอบเฉพาะชุดลงนามอีก **5/5 ผ่าน** ไม่อ้างว่า 18 กรณีที่ข้ามในรอบเฉพาะถูกรันซ้ำ
- Frontend **39/39 ผ่าน** เพิ่มกรณีกู้คืนข้อความ แยกบัญชี/คำร้อง/action หมดอายุ ข้อมูลเสีย ล้างเมื่อออกจากระบบ และ storage ใช้ไม่ได้
- build ทั้งสองฝั่งและ `git diff --check` ผ่าน deploy migration `20261104140000_course_change_signature_batches` ลง local แล้ว
- ตรวจจาก service บนฐาน local ว่ามีคำร้องสาธิต 4 รายการในขั้นที่เตรียมไว้และมีเวลารอ ตรวจ PDF fixtures ทั้งสองอ่านได้และมีหนึ่งหน้า backend health ปกติ
- **ยังไม่ได้ตรวจ interaction/visual/mobile ของหน้าจอใหม่ผ่านเบราว์เซอร์** เนื่องจากการเข้าถึง localhost ถูกเครื่องมือเบราว์เซอร์ปฏิเสธตามนโยบายที่พบก่อนหน้านี้ ไม่ใช้ผล API/unit tests แทนการอ้างว่าผ่าน UAT

ยังต้องยืนยันกฎวันตัดรอบ ผู้มีอำนาจลงนาม แบบและหลักฐานจริง รวมถึงแยกสิทธิ์ staff และเชื่อมระบบภายนอกตาม [รายการคงค้างเดิม](IMPLEMENTATION-2026-11-04.md)
