# หน้าจัดการสิทธิ์ (ขั้นที่ 5b) — Design

วันที่: 24 พ.ย. 2026 · สรุปจากการคุย brainstorming · ต่อจาก[แผนของกลาง](../plans/2026-11-23-shared-backend-objects.md) หัวข้อ 2.5 และ 3.8 (ส่วนที่ขัดกัน ใช้เอกสารนี้)

## ผลที่ตัดสินแล้ว

| เรื่อง | ที่เลือก |
|---|---|
| ขอบเขต | จัดการสิทธิ์ของผู้ใช้ + สร้างและแก้บทบาท (ไม่มีหน้าประวัติ ใช้หน้า audit ภายหลัง) |
| บทบาท | preset ที่ผูกติดกับผู้ใช้: ช่องที่มาจากบทบาทล็อกและแสดงที่มา แก้บทบาทครั้งเดียวมีผลกับทุกคนที่มีบทบาทนั้น |
| สิทธิ์รายคน | ให้เพิ่มได้อย่างเดียว ต้องมีเหตุผล |
| วันหมดอายุ | ไม่มี ทั้งบทบาทและสิทธิ์รายคน (ตัดออกจากแผนของกลางและขั้นที่ 5a) |
| การห้ามสิทธิ์ (deny) | ไม่มี สิทธิ์เป็นแบบเพิ่มอย่างเดียว การทำผิดกฎจัดการในโมดูลเจ้าของกฎ (เช่น storage ห้ามยืมเมื่อค้างค่าปรับ) กรณีร้ายแรงปิดบัญชี (`is_active`) |
| หน้าจอ | `/admin/access` สองแท็บ: ผู้ใช้ และ บทบาท จัดเรียงบนลงล่าง |
| การบันทึก | แก้เป็นร่าง แล้วกดบันทึกครั้งเดียว ใส่เหตุผลหนึ่งข้อ backend หาความต่างเอง |

## 1. ข้อมูลและกติกา

**ตาราง** (สร้างในขั้นที่ 5a ขั้นนี้ไม่เพิ่มตาราง)

| ตาราง | คอลัมน์ |
|---|---|
| `roles` | `key` (unique), `name`, `description`, `is_system`, `is_active` |
| `role_permissions` | `role_id`, `permission` |
| `user_roles` | `user_id`, `role_id`, `granted_by`, `created_at` |
| `user_permissions` | `user_id`, `permission`, `reason`, `granted_by`, `created_at` |

**สิทธิ์ที่ใช้จริง** = สิทธิ์ของบทบาทที่เปิดใช้งานใน `user_roles` ∪ `user_permissions` ∪ สิทธิ์ของบทบาท `student` ถ้ามี `student_no`

**กติกา** (ตรวจใน backend ทุกครั้งที่บันทึก)
1. ชื่อสิทธิ์ต้องอยู่ใน `permissionCatalog` ที่โค้ดประกาศ
2. ให้บทบาทหรือสิทธิ์รายคนที่มีสิทธิ์ที่ตัวเองไม่มีไม่ได้ การถอนทำได้เสมอ
3. บทบาท `student` ได้อัตโนมัติ ให้หรือถอนไม่ได้ แสดงเป็นช่องล็อกของคนที่มี `student_no`
4. ต้องเหลือผู้ใช้ที่เปิดใช้งานและมีบทบาท `it_admin` อย่างน้อยหนึ่งคน ตรวจตอนถอนบทบาท และตอนปิดผู้ใช้ใน Master Data
5. บทบาทระบบ (`is_system`: `student`, `it_admin`, `audit`) เปลี่ยน key และปิดไม่ได้ แก้สิทธิ์ได้ แต่ `it_admin` ต้องมี `core.permissions.manage` เสมอ
6. key ของบทบาทตรงกับ `^[a-z][a-z0-9_]{1,40}$` และไม่ซ้ำ บทบาทไม่ลบ ใช้ `is_active = false` บทบาทที่ปิดไม่ให้สิทธิ์
7. การบันทึกที่มีการเปลี่ยนแปลงต้องมีเหตุผล 1–500 ตัวอักษร เก็บในสิทธิ์รายคนที่เพิ่มรอบนั้นและใน audit ทุกแถว

**audit** (ต้องมีขั้นที่ 4) หนึ่งแถวต่อหนึ่งการเปลี่ยนแปลง: `core.role.assigned`, `core.role.revoked`, `core.permission.granted`, `core.permission.revoked`, `core.role.created`, `core.role.updated` (`before` และ `after` เก็บชื่อ สิทธิ์ และ `is_active`)

## 2. Backend

**โครง**
- `src/core/access.ts`: คำนวณความต่าง ตรวจกติกา และเขียนใน transaction เดียวพร้อม `audit()`
- `src/modules/access/`: route ทั้งหมด (`name: "core"`) ทุก route `{ auth: "user", permission: "core.permissions.manage" }`
- `app.ts` แนบ `permissionCatalog` ด้วย `app.decorate` เพื่อไม่ให้โมดูล import `modules/index.ts` แบบวน

**แถวและคอลัมน์ของตาราง** ได้จากชื่อสิทธิ์: token แรกที่เป็น `use`, `view` หรือ `manage` คือคอลัมน์ ส่วนหน้าคือแถว ส่วนหลัง `manage.` คือส่วนย่อยในช่องจัดการ
- `course_change.manage.advise` → แถว `course_change` คอลัมน์ `manage` ส่วนย่อย `advise`
- `core.users.view` → แถว `core.users` คอลัมน์ `view`
- ทุกชื่อสิทธิ์จึงต้องลงท้ายหรือมีระดับอยู่ เปลี่ยน `core.import` เป็น `core.import.manage`
- ชื่อแถวภาษาไทย: `AppModule.label` (เช่น `ลด-ถอนรายวิชา`) และ core กำหนดแถวของตัวเอง (`core.users` = ผู้ใช้, `core.permissions` = บทบาทและสิทธิ์, `core.import` = นำเข้าข้อมูล)

**API**

| route | ทำอะไร |
|---|---|
| `GET /access/catalog` | แถวของตาราง `{ row, label, cells: { use?, view?, manage?: { key, parts: [{ key, label }] } } }` |
| `GET /access/users?q=` | ค้นชื่อ อีเมล รหัสนิสิต สูงสุด 10 คน: `id, name, email, studentNo, isActive, roles[]` |
| `GET /access/users/:id` | บทบาท, สิทธิ์รายคน (`reason`, `grantedBy`, `createdAt`), `effective: [{ permission, sources }]` source เป็นชื่อบทบาท, `"direct"` หรือ `"student"` |
| `PUT /access/users/:id` | `{ roleIds, permissions, reason }` = สถานะใหม่ทั้งหมด backend หาความต่าง ไม่มีอะไรเปลี่ยนคืน 200 ไม่เขียน มีเปลี่ยนต้องมี `reason` สิทธิ์รายคนที่ไม่เปลี่ยนคงเหตุผลเดิม คืนรายละเอียดใหม่ |
| `GET /access/roles` | ทุกบทบาท สิทธิ์ และจำนวนผู้ใช้ |
| `GET /access/roles/:id` | บทบาทเดียวพร้อมรายชื่อสมาชิก |
| `POST /access/roles` | `{ key, name, description, permissions, reason }` |
| `PUT /access/roles/:id` | `{ name, description, permissions, isActive, reason }` |

**error:** 422 `VALIDATION` (ชื่อสิทธิ์ไม่รู้จัก, key ผิดรูปแบบ, ไม่มีเหตุผล, ให้หรือถอน `student`), 403 `FORBIDDEN` (ให้สิทธิ์ที่ตัวเองไม่มี), 409 `CONFLICT` (IT Admin คนสุดท้าย, บทบาทระบบ), 409 `DUPLICATE` (key ซ้ำ)

**อื่นๆ**
- สิทธิ์โหลดใหม่ทุก request ไม่มี cache การเปลี่ยนจึงมีผลใน request ถัดไป ไม่ต้องล็อกเอาต์
- `PATCH /users/:id` ใน Master Data ที่ตั้ง `isActive: false` ตรวจกติกาข้อ 4
- สองคนแก้คนเดียวกันพร้อมกัน: บันทึกหลังสุดชนะ ทุกการเปลี่ยนอยู่ใน audit ไม่ทำ version lock

## 3. Frontend

**ที่อยู่:** `/admin/access` ครอบ `<RequireAuth permission="core.permissions.manage">` เมนู "สิทธิ์ผู้ใช้" (ไอคอนกุญแจ) แสดงเฉพาะคนที่มีสิทธิ์นี้

**แท็บผู้ใช้** (บนลงล่าง)
1. ช่องค้นหา (พิมพ์แล้วรอ 300 ms แสดงรายการเลือกแบบลอย สูงสุด 10 คน ปิดเมื่อเลือก) และปุ่ม "บันทึก (N)" ทางขวา กดได้เมื่อมีการเปลี่ยนแปลง
2. รายละเอียดและบทบาท: ชื่อ อีเมล สถานะ รหัสนิสิตพร้อม "นิสิต (อัตโนมัติ)" ชิปบทบาทพร้อม ✕ และ dropdown "+ เพิ่มบทบาท" (บทบาทที่เปิดใช้งาน ยกเว้น `student`) ของที่เพิ่มสีเขียว ของที่ถอนสีแดงขีดฆ่าจนกว่าจะบันทึก
3. ตารางสิทธิ์: แถวตาม catalog คอลัมน์ ใช้งาน / ดู / จัดการ (ส่วนย่อยอยู่ในช่องจัดการ)
   - มาจากบทบาท: ติ๊กและล็อก แสดงชื่อบทบาททุกตัว เช่น "อาจารย์, Audit"
   - สิทธิ์รายคน: ติ๊กและกดได้ hover เห็นเหตุผลและผู้ให้
   - "—" = โมดูลไม่มีระดับนั้น
   - ช่องและบทบาทที่ผู้ใช้หน้านี้ไม่มีสิทธิ์ให้ ปิดไว้ พร้อมข้อความ "ให้ได้เฉพาะสิทธิ์ที่คุณมี"

**บันทึก:** กดแล้วเปิดกล่องยืนยัน สรุปการเปลี่ยนทุกข้อ ช่องเหตุผล (บังคับ) ปุ่ม "ยกเลิก" และ "ยืนยัน" ถ้า backend ตอบ error แสดงข้อความในกล่องและคงร่างไว้ สำเร็จแล้วโหลดข้อมูลใหม่ เลือกคนอื่น สลับแท็บ หรือปิด/รีเฟรชหน้าตอนมีร่างค้าง ถามยืนยันก่อน (การกดเมนูไปหน้าอื่นใน `/admin` ยังไม่ถาม เพราะแอปใช้ `<Routes>` ไม่ใช่ data router จึงใช้ `useBlocker` ไม่ได้)

**แท็บบทบาท** (บนลงล่าง)
1. ช่องเลือกบทบาท ปุ่ม "+ สร้างบทบาท" และปุ่มบันทึก
2. ชื่อ คำอธิบาย สวิตช์เปิด/ปิด (ไม่มีในบทบาทระบบ) badge "ระบบ" และรายชื่อสมาชิก (อ่านอย่างเดียว เพิ่มหรือถอนที่แท็บผู้ใช้)
3. ตารางสิทธิ์ของบทบาท (ไม่มีล็อก)
- สร้างบทบาท: กรอก key, ชื่อ, คำอธิบาย แล้วติ๊กสิทธิ์ key แก้ไม่ได้หลังสร้าง
- บันทึกแบบเดียวกับแท็บผู้ใช้

**โครงโค้ด**
- `src/api/access.ts`: type และ hook ของ TanStack Query
- `src/features/access/`: `AccessPage` (แท็บ), `UserAccess`, `RoleEditor`, `PermissionMatrix` (โหมด `editable` / `locked` ใช้ทั้งสองแท็บ), `SaveChangesDialog`
- `src/features/access/matrix.ts`: logic ล้วน (สร้างตารางจาก catalog, รวมที่มา, หาความต่างของร่าง, ตรวจ "ให้ได้เฉพาะสิทธิ์ที่มี")
- ข้อความในหน้าเป็นภาษาไทย

## 4. การทดสอบ

**backend** `test/core/access.test.ts` (ใช้บัญชี `@test.local`)
- กติกา: ชื่อสิทธิ์ไม่รู้จัก → 422; `staff@test.local` เรียก `/access/*` → 403; `itadmin@test.local` ให้บทบาทที่มี `receipts.manage` → 403 แต่ถอนได้; ให้หรือถอน `student` → 422; ถอน `it_admin` คนสุดท้าย → 409; ปิด IT Admin คนสุดท้ายใน Master Data → 409; เปลี่ยน key หรือปิดบทบาทระบบ → 409; ถอด `core.permissions.manage` จาก `it_admin` → 409; key ซ้ำ → 409 `DUPLICATE`; มีการเปลี่ยนแต่ไม่มีเหตุผล → 422
- `PUT /access/users/:id`: เพิ่มบทบาท + เพิ่มสิทธิ์รายคน + ถอนบทบาทในครั้งเดียว → audit 3 แถว action ถูก เหตุผลเดียวกัน; บันทึกซ้ำสถานะเดิม → ไม่มี audit; สิทธิ์รายคนที่ไม่เปลี่ยนคงเหตุผลเดิม
- ที่มาซ้ำ: สองบทบาทให้สิทธิ์เดียวกัน ถอนหนึ่งตัวยังมีสิทธิ์ และ `GET /access/users/:id` แสดงที่มาครบ
- มีผลทันที: หลังบันทึก request ถัดไปของคนนั้นได้สิทธิ์ใหม่ (`GET /receipts` 403 → 200)
- บทบาท: สร้างและแก้เขียน `core.role.created` / `core.role.updated` บทบาทที่ปิดไม่ให้สิทธิ์
- การแยกชื่อสิทธิ์และ test ว่าทุกชื่อใน `permissionCatalog` แยกได้

**frontend** `src/features/access/matrix.test.ts` (vitest): สร้างตารางจาก catalog (แถว คอลัมน์ ส่วนย่อย "—"), รวมที่มา, หาความต่างของร่าง, ปิดช่องที่ให้ไม่ได้

**ทดสอบด้วยมือ:** ล็อกอิน `admin@cedt.edu` (มีทั้ง `staff` และ `it_admin`) ให้ `teacher@test.local` บทบาท Audit บันทึกพร้อมเหตุผล แล้วล็อกอินเป็น teacher เห็นเมนูเปลี่ยน; ลองถอน `it_admin` ของตัวเองตอนเป็นคนเดียว เห็นข้อความ error ภาษาไทย
